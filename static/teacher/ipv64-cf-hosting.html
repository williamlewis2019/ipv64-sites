IPv64 子域名托管到 Cloudflare 的方法

2026-11-23 · 本站三个域名的来历 · NS 委派实测

2026-11-23 实测跑通：student / teacher / doctor 三个 *.ipv64.de 子域名已全部委派到 Cloudflare 管理。

背景

IPv64.net 免费档给 3 个子域名，自带 DNS 管理够用，但记录类型、API 与自动化不如 Cloudflare 顺手。子域名本身可以作为一个独立的 DNS 区域（zone）委派出去——关键是父域 ipv64.de 愿意发布你给子域名设的 NS 记录。实测 IPv64 支持这一点。

步骤

  1. 在 Cloudflare 建 zone：用 API POST /zones，name 填完整子域名（如 doctor.ipv64.de），account_id 用自己的。Cloudflare 会给这个 zone 分配一对专属 NS（如 ariadne.ns.cloudflare.com / lennox.ns.cloudflare.com），zone 初始状态为 pending。
  2. 在 IPv64 侧加 NS 记录：用 IPv64 API add_record，praefix 留空、type 选 NS、content 填 Cloudflare 分配的 NS 主机名。两个 NS 各加一条，接口返回 201 即成功。IPv64 会把这两条 NS 作为委派发布出去。
  3. 等 Cloudflare 校验：CF 会周期性检查父域委派是否指向它分配的 NS。实测 2–3 分钟到两轮检查内，三个 zone 先后转 active。
  4. 核实：用公共 DNS（Google DoH 与 Cloudflare DoH 各查一次）确认子域名的 NS 已是 CF 的那一对。

注意事项

  • 之后这个子域名的所有解析记录都在 Cloudflare 里管，IPv64 侧不用再动。
  • IPv64 免费档的子域名上限是 3 个（API 512 次/天、TTL 最低 60 秒），自有域名接入是付费档功能。
  • 这是借来的域名：只适合自用基建（状态页、看板、文档站），不建议在上面沉淀对外产品。
