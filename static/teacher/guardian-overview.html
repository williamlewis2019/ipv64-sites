沙盒保活体系说明

2026-11-23 · CF 探针 + 三层保活 + Hermes + 自动审批

目的：Muse 的运行沙盒是平台管理的临时虚拟机，会被不定期重建。这套体系让重建后的环境自动恢复，不需要人工介入。

组成

  • CF 探针：部署在沙盒里的探针程序，定期向 Cloudflare Worker 后台（cf-server-monitor）汇报存活，后台可看在线状态。
  • 三层保活： 1. 沙盒内看门狗脚本，盯关键进程（探针、Hermes 网关、sshd、cron），挂了就拉起； 2. 平台定时巡检（每分钟一次健康检查），发现沙盒被重建就跑全量恢复脚本 restore-all.sh，从离线缓存把探针、网关、定时任务等一件件装回去； 3. 平台开机钩子，沙盒重启时先行触发一轮自检恢复。
  • Hermes 微信机器人：恢复完成、账号安全异常等需要人知道的事，经微信推送（推送通道偶有不稳，重要事项同时同步到主聊天）。
  • MuseAutoApprove：对 muse.ai 的外联审批卡按既定策略自动批准，免得定时任务卡在审批上。

通知节流

沙盒重建有时一天多次，全是自动恢复成功的小事，所以通知做了节流：距上次通知满 6 小时才发一条，中间的恢复次数合并汇报；恢复失败则不受节流影响，立即通知。

备份

保活脚本与配置有一份离线备份仓库（私有，密钥类文件故意排除在外）。恢复脚本幂等，可安全重跑。

已知教训

  • 沙盒重建会清掉 /root，SSH 配置等要从持久区复制回去再用。
  • 经 SSH 传文件后必须验大小或 md5——有过一次传输卡死把脚本截成 0 字节的事故。
  • 「恢复成功」以恢复日志的收尾标记 + 恢复后健康检查退出码为准，不看中间输出。
